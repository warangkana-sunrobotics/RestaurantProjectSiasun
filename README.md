## How to use the database

1. Git pull the lastest version

2. Copy ".env.example" to ".env" and fill the real values( password, FERNET_KEY, API_KEY ). Never commit ".env".

3. On the project directory run "docker compose up -d --build"

4. Use the api by following the API postgres topic

## Customer web page( ordering + bill )

- Open http://127.0.0.1:8000/ ( FastAPI serves the page from the web/ folder, same origin, no CORS needed )
- The page uses /api/* : GET /api/menu, POST /api/orders, GET /api/orders/table/[ table no ], POST /api/orders/checkout
- Price and menu name always come from the "menu" table on the server. The page only sends menuId + quantity.
- Menu / order / bill are public( the customer has no key ) but rate limited per IP( RATE_LIMIT_READ / RATE_LIMIT_WRITE in .env ).
- Checkout( close the bill ) is for STAFF: the page asks for the API key when the button is pressed. The key is never written in the page.
- Number of tables = TABLE_COUNT in .env( must match the dropdown in web/index.html ).
- Change the menu or price: UPDATE public.menu SET price = 60 WHERE menu_id = 2;  or  SET available = false  to hide the item.
- Orders keep status open / paid( checkout does not delete the data ).
- Existing database: run docker/postgres/migrations/002_web_orders.sql( safe to run many times ).
- Known limit: the table number is chosen on the page, so any customer can see / order for another table. Use a QR code per table with a token if needed.

## Security notes( production )

- Every /restaurant/* request must send the header "X-API-Key: [ API_KEY in .env ]", missing/wrong -> 401. If API_KEY is empty the API reject everything( 503 ).
- Put the HTTPS reverse proxy( nginx / caddy ) in front of port 8000, the API itself does not provide TLS.
- Postgres port is bound to 127.0.0.1 only. Do not publish it to the internet.
- Swagger( /docs ) is off, set ENABLE_DOCS=true only on the dev machine.
- If .env / FERNET_KEY was ever pushed to git, treat it as leaked and generate the new one.
- airflow.yml / config/webserver_config.py are for local dev( Airflow UI without login ). Do not expose them.

## API postgres

- [ localhost ]/restaurant/getOrders?limit=100&offset=0
: Select all the order which all table( paginated, limit max 1000 ).

- [ localhost ]/restaurant/getOrders/[ table Id ]
: Select all the order which was select table id.

- [ localhost ]/restaurant/delOrders/orderId/[ order Id ]
: Delete only the order id which match in the api

- [ localhost ]/restaurant/delOrders/tableId/[ table Id ]
: Delete all the order which in the table id

- [ localhost ]/restaurant/insertOrder
: Insert the order into the database which was follow the json type

Example of use

1. http://127.0.0.1:8000/restaurant/getOrders -> Test by using postman with GET method

2. http://127.0.0.1:8000/restaurant/getOrders/2 -> Test by using postman with GET method

3. http://127.0.0.1:8000/restaurant/delOrders/orderId/0 -> Test by using postman with DELETE method

4. http://127.0.0.1:8000/restaurant/delOrders/tableId/1 -> Test by using postman with DELETE method

5. http://127.0.0.1:8000/restaurant/insertOrder -> Test by using postman with POST method( return 201 and the new order_id, the order_id is generated by the database, do not send it )

All requests need the header X-API-Key. Delete on the not-exist order return 404.

Select Body praser and use raw to insert the information of json type( like this : {
    "table_id": 3,
    "menu": "Hamburger",
    "cost": 100
} )
